# 概念学习资料生成 Skill

## 适用场景

- 学习一个新概念时，需要一份**结构化、可复查、可沉淀**的学习资料，而不是一段一次性的聊天回复。
- 需要把学习成果保存为 HTML 文件，放入个人学习仓库（如 `learning-materials/` 目录），长期积累并复习。
- 适合概念型知识（如 AI、编程、统计中的术语与机制）；不适合操作性教程（如"如何安装软件"）或纯新闻资讯。

## 输入信息

| 输入 | 必需 | 说明 |
|---|---|---|
| 概念名称 | 是 | 例如：Agent、大模型的上下文、Skill |
| 学习者已有认知 | 否 | 学习者对该概念的原有理解、困惑点，用于写"个人解释" |
| 输出文件名 | 否 | 默认为概念的英文短横线命名，如 `llm-context.html` |
| 输出目录 | 否 | 默认 `learning-materials/` |

最小调用示例：「用 concept-study-guide 学习"检索增强生成（RAG）"」

## 生成步骤

1. **确认概念边界**：先与学习者确认概念指什么（一个词可能有多个含义，如 Skill 在本课程中指 AI Agent 的能力包，而非"技能"的泛称）。
2. **检索与核实**：查阅权威来源（官方文档、经典论文、教材、知名技术博客），至少找到 2～3 条可核查的链接；记录每条来源支撑了资料中的哪个部分。
3. **设计学习目标**：写出 3～5 条"学完后应该能做什么"的目标，用可验证的行为动词（能解释、能区分、能举例）。
4. **提出核心问题**：围绕概念提出 3～4 个核心问题，作为资料的骨架。
5. **撰写结构化解释**：按输出结构逐节撰写；"个人解释"一节必须基于学习者输入的已有认知改写，不得整段照搬任何来源或 AI 原话。
6. **编写自测题**：出 3～5 道自测题（判断、辨析、举例题均可），并附参考答案要点。
7. **落盘输出**：生成 HTML 文件到指定目录，并在 README 的学习资料清单中登记。

## 输出结构

每份学习资料为一个独立 HTML 文件，依次包含：

1. **标题与一句话定义**（自己组织的语言，不超过 50 字）
2. **学习目标**（3～5 条）
3. **核心问题**（3～4 个，后续各节逐一回答）
4. **我的个人解释**（用自己的话，联系已有知识，标注不确定之处）
5. **核心机制 / 组成部分**（可用列表、表格或图示说明）
6. **一个具体应用场景**（真实、具体，说明概念在其中解决了什么问题）
7. **易混淆问题与使用边界**（和什么概念容易混？什么情况下不适用？）
8. **自测题**（3～5 题 + 参考答案要点）
9. **参考来源**（每条含标题、链接、一句话说明它支撑了资料哪部分）

## 资料来源要求

- **禁止伪造来源**：所有链接必须是真实存在、生成时已访问或明确可信的页面；不确定的来源宁可不写。
- 来源优先级：官方文档 > 原始论文/标准 > 教材 > 知名从业者的技术文章 > 百科类页面。
- 每条来源必须注明它支撑了资料的哪个部分，便于日后核查与修订。
- 若概念存在争议或版本差异（如不同框架对 Agent 的定义不同），须在"易混淆问题"中明确指出。

## 自检要求

生成后、提交前，逐项自检：

- [ ] 概念边界是否已与学习者确认，未写错所指？
- [ ] "个人解释"是否为学习者视角的表达，而非照搬 AI 或来源原文？
- [ ] 每个核心问题是否都有对应章节回答？
- [ ] 应用场景是否具体（有时间、对象、前后变化），而非空泛套话？
- [ ] 使用边界是否真实存在（能说出"什么情况下不适用"）？
- [ ] 自测题答案要点是否正确？
- [ ] 每条参考链接是否真实可访问？是否标注了支撑内容？
- [ ] 文件是否已保存到约定目录，且在 README 中登记？

任何一项不通过，先修正再输出；无法自行修正的，明确向学习者指出待人工核查的位置。
